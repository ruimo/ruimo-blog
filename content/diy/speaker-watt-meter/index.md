# 概要

オーディオアンプの出力は、どのくらい必要なのか。世の中には数100Wのアンプもあるが、そのような大出力アンプは本当に一般家庭に必要なのだろうか。

音の大きさはアンプの出力とスピーカーの能率で決まるため、アンプの出力だけを論じても仕方が無い。今回は90dBのスピーカーを用いて一般家庭の部屋で聴いた時にどのくらいの出力が必要なのかを測定した。その結果、最大時には60W強の電力が出力されていることが観察された。

# 目的

まだ、小学生の頃に「初歩のラジオ」とか「ラジオの製作」という雑誌があった。この時期(50年くらい前)はオーディオの製作記事がはやりで「なぜラジオの雑誌にオーディオばかりが掲載されるのだろう」と疑問に思いながらも熱心に読みふけったものだ。その中の記事の1つに「家庭でのアンプ出力は10Wもあれば十分で、5Wも出せば近所迷惑になる」といった記述があり、それ以来、自分は大した疑問も持たずにずっとこの記述を信奉してきた。

今はD級アンプがあるため、100W出力のアンプでもとても小さく、価格的にも手頃になったが、内心ではそんな出力は必要ないと思っていた。しかし当時の技術に想いを馳せると、あの10Wとか5Wとかは「定常」出力で測定したのではないだろうか。つまり正弦波のような定常的な信号のケースではないかということだ。これなら当時の測定器でもオシロスコープで測定可能だっただろう。

音楽のような信号では過渡的な出力は、実はずっと大きかったりしないだろうか。これを明らかにするのが今回の目的である。

# アプローチ

スピーカーにかかる電力を測定するには、電圧と電流を測定して乗算すれば良い。電圧はスピーカー両端の電圧を見れば良く、電流は直列にシャント抵抗を入れてその電圧降下を測定すれば良い。

![](howtomesure.svg)

過渡特性を見るためには、この電圧と電流を短い間隔で測定してその乗算結果を記録すれば良いことになる。考慮点は以下の通り。

- 電流と電圧は「同時」に測定する。ずれると正確な電力が測定できない。
- シャント抵抗は0.1Ωとした。
- D級アンプはBTL構成が多いので、左右チャネルでGNDを共通にできない。差動増幅で受ける必要がある。
- サンプリング周波数は40kHzとした。

## シャント抵抗

0.1Ωだと一般にはセメント抵抗が一般的だが、今回は[金属板抵抗器 ](https://akizukidenshi.com/catalog/g/g110697/)を使用した。[測定結果](https://www.ruimo.com/blog/speakerwatmeter2/)によると、高周波特性がセメント抵抗よりも良好である。

![](https://akizukidenshi.com/img/goods/L/110697.jpg)

# 構成図

アナログ部は、OPアンプによる差動増幅によりスピーカーの電流、電圧を測定。これをマイクロコントローラー[CH32V203](https://akizukidenshi.com/goodsaffix/CH32V203.pdf)のA/D変換器で受ける。CH32V203には2つのA/Dを同時起動する仕組みがあるので、これを用いて電流と電圧を同時に測定する。測定データをPCなどで取り出したいのでCH32V203で測定したデータは[ESP32](https://akizukidenshi.com/goodsaffix/esp32-wroom-32e_esp32-wroom-32ue_datasheet_en.pdf)に集めてWeb socketでPCに送れるようにする。ESP32はマイクロコントローラとWifiがセットになったチップで、今回のような用途にぴったりである。

## デジタル部

### A/D変換

A/D変換はCH32V203を用いた。これは2つのA/D変換を同時起動でき、今回の目的に合っていたためである。A/D変換の速度は14MHzまで対応しているので十分である。

![](2026-10-18-07-26-56.png)

処理能力的には少々オーバースペックではあるが、100円程度で購入できる([2026/10現在、AliExpressで10個1,000円くらい](https://ja.aliexpress.com/item/1005005304982586.html))ので問題無い。欠点はピン間0.65mmの48ピンパッケージ(QFN48)なので半田付けが面倒なことくらいである。

![](ch32v203.png)

CH32V203のアナログ入力電圧の上限は、VCC+0.3Vまで。一方、アナログ部の電源は5Vなので、そのままだと入力が過大な時に破損のリスクがある。

![](2026-10-18-07-28-10.png)

![](2026-10-18-07-20-08.png)

そこでショットキーバリアダイオード[RB521G-30](https://akizukidenshi.com/catalog/g/g113956/)でクランプしてある。

![](2026-10-18-07-21-58.png)

このダイオードは非常に順電圧が小さくて優秀なのだが、パッケージがSOD723(1mm x 0.6mm)で半田付けがなかなかに困難なのが欠点。

1秒に40000回A/D変換を起動する方法は、当初はタイマー割り込みを使っていた。しかし、それだと左右で測定タイミングがずれる。左右で少々ずれる分にはそれほど問題はないが、できれば揃えたい。そこで、PWMで40kHzを生成してPB0から矩形波を出力し、それを両方のCH32V203のPA11に入力。これで直接A/Dを起動するようにした(これは割り込みではなく、ハードウェアの機能である)。

A/D変換の出力はDMA駆動に設定して、出力先は循環バッファとした。つまりA/Dからの取り込みは全てハードウェアで実行されCPUが何もしなくても着々と進む。もちろん循環バッファは1周すれば過去のデータが上書きされてしまうので、その前にデータを取り出さなければならない。

![](ad.svg)

### CH32V203からESP32への転送

CH32V203は左右チャネルで2つあり、そこからESP32へA/D変換結果を転送する必要がある。A/D変換は12bit長である。電流と電圧があり24bit、左右があるので48bit。これを1秒に40,000回送るため、およそ2Mbps必要になる。

$$
bps = 24 \cdot 2 \cdot 40000 = 1920000 = 1.92Mbps
$$

この速度になるとSPIで決まりであろう。ESP32がマスター、CH32V203側がスレーブとなって交互にA/D変換結果を収集する。

![](ch32v203-esp32.svg)

今回の転送スピードだと、データのロストがあった際に検出が困難である。そこで転送データにはシーケンス番号を入れることにした。

```text
 bit: 31        24 23        12 11         0
     +------------+------------+------------+
     |  seq (8)   | adc2 (12)  | adc1 (12)  |
     +------------+------------+------------+
```

1サンプリングは32bit長になっておさまりが良い。8bitのシーケンス番号なので丁度256パケット失われたら検出できないが、そのようなケースばかり発生することはあり得ないだろう。当初は、SPIのCSアサートで割り込みをかけ、SCLK開始までにSPI転送データを準備するようにした。

![](spi-timing0.svg)

しかしこれは典型的なrace conditionである。SCLKのタイミングが速ければデータの準備が間に合わない状態でSPI転送が開始してしまう。絶妙なタイミングで間に合うかもしれないし間に合わないかもしれない。結果はたまに起きるデータの破損である。こういう設計は避けるべきであろう。

そこでSPIデータはインターリーブして準備することにした。SPI転送が終わるとCSがデアサートされる。ここで割り込みをかけてSPI転送データを準備する。転送はDMAを用いるので、次のSCLKのタイミングでCPUの介在無しにDMAだけを用いて転送が実施される。転送は左右交互に行われるので、反対チャネルの転送時間の間に自分のSPI転送データを準備できれば良い。

![](spi-timing1.svg)

### UI

UIは[egui](https://github.com/ruimo/speakerWattMeter/tree/main/controller)を用いてRustで実装している。完成版はブラウザー上でWeb assemblyで動作し、ESP32とはweb socketで通信する。Web assemblyのプログラムはESP32上に格納され、ブラウザでアクセスするとブラウザにダウンロードされて実行される。

![](ui-browser.svg)

完成版はこれで良いが、開発中はWeb assemblyを毎回ESP32に書き込まなければならず生産性が悪い。そこでローカルアプリケーションとしても動作するようにした。eguiを利用しているので、ここはビルド方法を変更するだけで対応可能だ。この場合はWeb assemblyは使わずにローカルアプリケーションとESP32がWeb socketで通信する。

![](ui-local.svg)

UIでは、電流、電圧、電力の波形と、これまでに記録された瞬間最大電力を記録するようにした。またキャリブレーション機能を用意した。これは

- 入力ゼロでのA/D変換結果の収集
- 8Ωのダミーロードで、一定入力(例: 4V/0.5A)でのA/D変換結果の収集

を実施して、その結果をESP32のフラッシュに記録する仕組みである。

Web assemblyはESP32に書き込まれるため、フラッシュの容量がそれなりに必要である。8MBあれば十分のようだが、価格も大して変わらないため今回はESP32-N16R8を使用した。[AliExpressで2026/10現在、500円ほどで入手できる](https://ja.aliexpress.com/item/1005009314619102.html)。

- [UIの詳細](https://github.com/ruimo/speakerWattMeter/tree/main/ui)

# 測定結果

最後に測定結果をお見せしたい。

### アンプ

[AIYIMA A07](https://ja.aliexpress.com/item/1005008529243001.html)を使用。私が購入した時はセールになっていて8,000円を切っていた。欲張りを言えば、もう少し電源スイッチの質感が良いと嬉しいが、この値段でそれを望むのは贅沢だろう。

![](2026-10-18-09-22-16.png)公称300W x 2出力。ACアダプターには48V 10Aのものを使用しているが、こちらも約8,000円だった。

### スピーカー

[B&W S702 Signature](https://www.bowerswilkins.com/ja-jp/product/loudspeakers/702-s3-signature/FP43540P.html)を使用。効率は90dB。

### スピーカーケーブル

[カナレの4S11](https://www.canare.co.jp/products/cables/index.php?tid=4_008)。こちらは久しぶりにヤフオクを利用。10mで5,000円ほどだった。馬鹿みたいに高い怪しいケーブルよりも、こちらをお勧めしたい。

![](https://www.canare.co.jp/products/image/prod_04/008_001.jpg)

# 結論

90dBのスピーカーを用い、一般家庭でのアンプの過渡的な電力出力を測定した。その結果、瞬間的には60W強の電力が必要であることが分かった。式は以下の通り。

$$
W = 60\text{ W} \cdot 10^{\frac{(90 - n)}{10}}
$$

能率が80-95までの計算値は以下の通り。もちろん、これは私の感覚であるし、部屋のコンディションにも影響されるので参考程度として欲しい。

| 能率 n (dB) | 必要電力 (W) |
|---:|---:|
| 80 | 600.0 |
| 81 | 476.6 |
| 82 | 378.6 |
| 83 | 300.7 |
| 84 | 238.9 |
| 85 | 189.7 |
| 86 | 150.7 |
| 87 | 119.7 |
| 88 | 95.1 |
| 89 | 75.5 |
| 90 | 60.0 |
| 91 | 47.7 |
| 92 | 37.9 |
| 93 | 30.1 |
| 94 | 23.9 |
| 95 | 19.0 |

価格.comで見るとブックシェルフタイプだと能率80dBくらいのものも少なからずあるため、こうしたスピーカーだとそれなりのアンプ出力が必要であることが分かった。つまり数100W出力のアンプには、ちゃんと存在理由があるのだ。

これで長年の疑問がようやく解けた。
